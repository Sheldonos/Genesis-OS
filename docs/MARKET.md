# Market and Business Model

## Market position

Genesis should not compete as another agent framework. That layer is crowded and rapidly commoditizing.

The stronger category is **intelligence control plane / capability operating system**:

- vendor-neutral models
- vendor-neutral agents
- vendor-neutral tools
- persistent organization/world state
- policy and identity that survive model changes
- outcome-based learning
- capability compilation

## Competitive landscape

### Agent frameworks

Examples: OpenAI Agents SDK, crewAI, DeerFlow, atomic-agents.

They solve orchestration and execution. Genesis should interoperate rather than replace all of them.

### Agent company/control planes

Paperclip validates demand for goals, org charts, budgets, agent identity, heartbeats, and run accounting. Genesis extends the idea downward into the capability/policy/memory kernel so a company control plane is one possible UI, not the architecture itself.

### Personal assistants

OpenClaw/Hermes/Airi-class systems validate persistent channels and user-facing presence. Genesis can power a personal shell while also supporting enterprise/domain deployments.

### Memory vendors

Cognee/Supermemory/memU/OpenMemory validate that long-term context is a standalone infrastructure category. Genesis should avoid lock-in by treating memory backends as providers while keeping a portable canonical state model.

### Computer-use and sandbox vendors

Browser Use/CUA/E2B/NemoClaw show that actuation and isolation are becoming infrastructure layers. Genesis should route among them rather than owning a browser engine or sandbox implementation.

## Defensible wedge

The moat is not "more agents." It is the accumulating **capability graph + evaluated procedures + outcome history + organizational world model**.

A customer that operates Genesis for a year should own a growing library of validated procedures specific to its business. Those procedures can be deterministic workflows, code, skills, policies, or model-assisted plans.

## Initial product

### Genesis Control Plane

A deployable service with:

- capability registry
- connectors/skills catalog
- goal runner
- policy editor
- approval inbox
- run traces/costs
- memory/world model
- procedure compiler
- evaluation dashboard

### Monetization

1. Open-source kernel (Apache-2.0)
2. Managed control plane per seat + compute
3. Enterprise private deployment
4. Governed connector/capability marketplace
5. Domain packs (research, education, media, finance research, GTM, operations)
6. Evaluation/observability and compliance tier

## Why now

The interoperability substrate is converging: MCP is becoming a routable tool/data/task protocol, A2A handles cross-agent communication, and portable skills are emerging as a standard packaging pattern. That makes a neutral state/policy/learning control plane more viable because Genesis does not need to invent every integration protocol.
